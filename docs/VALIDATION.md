# MVP 검증 기록

2026-10-12, Windows / Python 3.11에서 확인했습니다.

## 자동 검증

`python -m pytest -q`로 API 키 없이 엔진, REST/WebSocket, 공급자 인터페이스 테스트를 수행합니다. 핵심 검증은 `tests/`에 있으며 CI에서도 같은 명령을 실행합니다.

Mock에서 확인한 항목:

- 추가 사용자 발언 없이 세 에이전트가 대화하고, 발언 순서가 동일한 3명 순환으로 반복되지 않음
- 동시에 요청한 3명의 중재 점수가 기록되며 한 명만 스트리밍함
- 사용자 개입 시 중단 이벤트가 먼저 기록되고, 이미 나온 내용과 사용자 발언을 보존함
- 에이전트가 내용·의지·관련성 조건에 따라 다른 에이전트 발언을 중단함
- 낮은 판단에 따라 정적에 들어가고, 실제 재평가 후 다시 발언함
- 연상 발언과 원래 주제를 다시 언급하는 발언이 기록됨
- 일시정지·종료 시 진행 중인 생성기와 비동기 루프를 닫음
- 특정 에이전트의 네트워크 오류가 다른 에이전트의 발언을 막지 않음
- 호출 예산과 출력 길이 제한, 오래된 요청 무효화, 느린 구독자 복구 신호
- JSON 판단 응답과 SSE 스트림, 429 대기, 잘못된 JSON 격리

이는 스케줄러·상태 전환의 기능 검증입니다. Mock의 자연스러움과 창의성은 평가하지 않습니다.

## 실제 무료 API

Groq 계정 화면에서 **Free / $0 / Current Plan**을 확인하고 Bstom 전용 키를 로컬에 저장했습니다. 공개 저장소에는 키와 실제 세션 기록을 포함하지 않습니다.

`scripts/live_smoke.py --live`를 Qwen `qwen/qwen3.8-27b`로 실행한 결과:

- 총 12회 실제 호출
- 실제 스트림 도중 사용자 개입 및 부분 발언 보존 확인
- 완성된 AI 발언 3개, 두 에이전트의 이어 말하기 확인
- 공급자 오류 0회
- 무료 API 분당 한도를 지키는 대기 후 대화 재개 확인

세 번째 에이전트가 반드시 같은 횟수로 발언하도록 강제하지 않습니다. 이 짧은 실제 실행에서 세 에이전트 모두의 발언, 장시간 자연스러움, 실제 과학 내용의 정확성은 검증하지 않았습니다. 과학적 추측이나 모델 발언은 그대로 사실로 받아들이지 마세요.

별도의 최종 Chrome 실행에서는 넓은 웹 서비스 주제만 입력한 뒤 솔·나루·미오가 모두 실제 AI 발언을 했고, 화면에서 무료 한도 대기 상태가 표시되는 것도 확인했습니다. 따라서 세 에이전트의 실제 자율 발언은 추가 실행에서 확인했지만, 장시간 자연스러움은 여전히 미검증입니다.

## 웹 화면

Chrome에서 정확한 Bstom 페이지 제목과 로컬 서버 응답을 확인했습니다. 주제 입력, 실시간 상태·대화·이벤트, 일시정지·재개·종료, 사용자 메시지 입력, 기록 조회는 브라우저 확인과 REST/WebSocket 테스트로 나누어 검증합니다.

## 알려진 한계

- 무료 할당량 때문에 판단·발언이 수십 초 기다릴 수 있습니다. 이 시간은 엔진의 정적과 별도의 API 대기 상태입니다.
- 스케줄러의 토큰 예약은 추정치이고 공급자의 실제 한도·다른 앱 사용량은 콘솔에 따릅니다.
- 모델의 반복, 과장, 사실 오류를 완전히 막지는 못합니다.
- 최근 문맥과 짧은 개인 기억을 사용하므로 오래된 세부 사항이 소실될 수 있습니다.
- 서버 재시작 후 기록 조회는 가능하지만 진행 중이던 세션 재개는 지원하지 않습니다.
- 무인 서버 운영·로그인·공개 인터넷 서비스용 보안 설계는 범위에 포함하지 않았습니다.
