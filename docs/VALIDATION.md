# MVP 검증 기록

2026-10-12, Windows / Python 3.11에서 확인했습니다.

## 자동 검증

`python -m pytest -q`: **32개 통과**. API 키 없이 엔진, REST/WebSocket, 공급자 인터페이스와 데스크톱 엔진 연결을 검증하며 CI에서도 같은 명령을 실행합니다.

- 사용자 추가 입력 없이 세 에이전트가 대화하며 동일한 3명 순환을 강제하지 않음
- 동시에 요청한 3명의 중재 점수가 기록되고 한 명만 발언을 생성함
- 경쟁하는 에이전트들은 완성된 채팅을 보존하며 다음 발언을 요청함
- 사용자 입력 시 진행 중인 생성 또는 표시 대기를 취소하고 사용자 발언을 즉시 기록함
- 이미 표시한 채팅은 유지하고, 아직 보이지 않은 내용은 기록과 다음 판단에 넣지 않음
- 첫 채팅에 추가 표시 지연이 없고 각 채팅 전체를 `speech_chunk` 한 번으로 전달함
- 채팅 사이 읽기 간격 동안 다음 내용을 생성하며, 생성 시간도 간격에 포함함
- 오류가 난 미완성 채팅을 노출하지 않고 생성기를 닫음
- 웹의 별도 발언 생성과 로컬의 판단·발언 통합 생성에서 입력 중 상태를 전달하고 스냅샷·이벤트에서 복원하며, 발언 완료·사용자 취소·오류·일시정지 시 해제함
- 낮은 발언 의지에도 재평가와 새 발언 요청을 계속 처리함
- 별도 정적 상태·이벤트와 Mock의 주기적 발언 억제 규칙이 없음
- 연상 발언과 초기 주제를 다시 언급하는 발언이 기록됨
- 일시정지·종료 시 진행 중인 생성기와 비동기 루프를 닫음
- 특정 에이전트의 네트워크 오류가 다른 에이전트를 손상시키지 않음
- 선택적 호출 예산·분당 제한, 출력 길이, 오래된 요청 폐기, 전역 동시 호출 제한
- 느린 구독자 복구, REST/WebSocket 제어, 공급자 JSON/SSE/429 오류 처리
- Ollama 통합 응답을 한 번 생성하고 선택된 에이전트의 준비된 말만 공개함
- 세션별 준비된 말 격리, 사용자 개입 이전 말 폐기, 사고 과정 제외, 미완료 로컬 스트림 오류 처리
- 로컬 호출에서 키·프록시·외부 주소·클라우드 모델을 사용하지 않음
- 메시지·시간 제한 0을 무제한으로 처리하며 데스크톱 종료 시 작업과 모델 연결을 정리함

이는 기능 검증입니다. Mock으로 자연스러움이나 창의성을 평가하지 않습니다.

## 로컬 데스크톱 검증

검증 PC는 i7-1260P, RAM 16GB, RTX 2050 VRAM 4GB입니다. Ollama 0.40.2를 사용했습니다. 처음에는 속도 때문에 `qwen2.5:3b`를 선택했지만 표현이 아쉬워 같은 날 기본 모델을 `gemma3:4b`로 변경했습니다.

실제 데스크톱 엔진 연결로 28.84초 동안 8회 로컬 호출, 세 에이전트의 완성된 발언 4개, 사용자 개입, 입력 중 이벤트, 일시정지와 종료를 확인했습니다. 공급자 오류는 없었습니다. 첫 호출은 9.92초였고 이후 6회 생성은 2.47~3.50초, 평균 2.90초였습니다. 이는 해당 PC·짧은 대화의 생성 시간이며 모든 상황의 메시지 간격을 보장하지 않습니다. 작은 모델에서 부자연스러운 한국어와 지어낸 음식 이름도 관찰해 자연스러움 검증을 완료한 것으로 보지 않습니다.

### 모델 변경 비교

음식 취향, 혼자 사는 사람을 위한 웹 서비스, 화분 단톡방 농담이라는 세 가지 합성 대화를 같은 구조화 응답 방식으로 비교했습니다. 지시문도 순차 개선했으므로 모델만의 공정한 대조 실험은 아닙니다. 다음 평가는 이 짧은 샘플을 직접 읽은 판단이며 표준 한국어 벤치마크 점수가 아닙니다.

| 모델 | 준비된 상태의 두 샘플 생성 시간 | 관찰 |
| --- | --- | --- |
| Qwen2.5 3B | 3.72~4.89초 | 반복, 문맥 오해, 어색한 어휘가 남음 |
| Qwen3 4B Instruct 2507 | 9.61~10.83초 | 이 샘플에서는 의미가 어색한 표현과 연결이 남음 |
| Qwen3.5 4B (기존 지시문) | 17.16~23.38초 | 더 느렸으며 이 샘플의 표현 개선이 뚜렷하지 않음 |
| Gemma 3 4B (GPU 전체 사용) | 8.45~9.31초 | 더 자연스러운 수다와 농담; 기본값으로 선택 |
| EXAONE 3.5 2.4B | 3.52~3.86초 | 한국어 문장은 매끄럽지만 설명하는 말투가 많음; 선택 가능한 대안 |

고정 한 문장·20~60자 지시와 빵 이야기 예시를 없앴습니다. 실제 발언을 이름과 시간 순서가 보이는 대화로 전달하고, 사용자 발언을 에이전트 자신의 발언으로 혼동하지 않도록 구분했습니다. 사적인 기억은 실제 발언과 별도로 전달하며 한마디 또는 짧은 두 문장을 허용합니다.

Gemma는 자동 GPU 배치에서 두 샘플이 14.39~15.97초였고, `OLLAMA_GPU_LAYERS=99`로 이 PC의 GPU에 전부 올린 후 8.45~9.31초였습니다. `/api/ps`의 전체 모델 크기와 GPU 크기가 같음을 확인했습니다. 일반 배포 기본값은 -1(자동)이며 99는 이 PC에서 검증한 로컬 설정입니다.

새 Gemma 엔진에서도 세 에이전트의 발언 4개와 사용자 개입, 일시정지·종료를 70.41초 동안 확인했습니다. 8회 호출이며 공급자 오류는 없었습니다. 첫 생성은 20.40초였고 이후 6회는 6.00~9.25초였습니다. 사용자 개입은 이전 문맥의 준비된 말을 폐기하므로 표시 간격은 개별 생성 시간보다 길 수 있습니다. 질문 반복, 문맥 오해, 어색한 영어가 일부 남아 있어 대화 품질 개선을 완료했다고 보지는 않습니다.

Windows의 실제 Tk 창을 실행했고 창 제목과 오류 로그를 확인했습니다. 네이티브 화면의 모든 버튼을 자동으로 클릭하는 시각 검증은 하지 않았습니다. 화면과 엔진 사이의 사용자 발언·일시정지·재개·종료·기록 저장은 자동 연결 테스트로 검증했습니다.

데스크톱은 호출·메시지·시간 제한과 추가 채팅 간격을 모두 0으로 설정합니다. 생성이 완료되면 완성된 채팅을 즉시 표시합니다. 모델 가중치는 하나를 공유하지만 각 에이전트의 판단·기억·발언 요청은 독립적입니다. 작은 GPU에 맞춰 생성은 한 번에 하나씩 처리하며 준비 중인 에이전트에 입력 중 표시가 나옵니다. 실제 생성 시간이 필요하며 사용자 입력은 즉시 기록됩니다.

## 웹 디버그 화면 표시 방식

타이핑 효과 없이 완성된 채팅을 한 번에 표시합니다. 첫 채팅은 생성 완료 후 바로 나오고, 이후 채팅은 이전 메시지 표시 시각부터 기본 1초에 글 길이 ÷ 200초를 더한 간격을 적용합니다. 기본 설정에서 읽기 간격은 최대 1.5초입니다.

생성은 이 간격과 동시에 진행합니다. API 응답이 간격보다 늦으면 준비되는 즉시 표시합니다. 사용자 메시지는 즉시 표시하고, 그 메시지 다음 AI 발언에도 읽기 간격을 적용합니다. 답변 생성·표시 대기 동안 선택된 에이전트의 이름과 입력 중 표시가 나옵니다. 빈 말풍선이나 중단 배지는 표시하지 않습니다. 취소 사실은 이벤트 로그에 남습니다. 별도의 Mock 웹 테이블에서 에이전트 카드와 입력창 위에 이름·입력 중·움직이는 점 세 개가 나타나고, 일시정지하면 즉시 사라지는 것을 브라우저로 확인했습니다.

## 이전 Gemini 공급자 검증

Google AI Studio에서 Bstom 전용 Gemini 키를 무료 등급 프로젝트에 발급해 `.env.local`에 저장했습니다. 공개 저장소에는 키와 실제 세션 기록을 포함하지 않습니다. 웹의 Gemini 기본 모델은 `gemini-3.5-flash-lite`이며 로컬 데스크톱에서는 사용하지 않습니다.

네이티브 `generateContent`로 JSON 판단, `streamGenerateContent`로 SSE 응답을 생성합니다. 별도 공급자의 키가 Gemini로 전송되지 않는 것, 사고 과정 제외, 사용량 보정, 차단·빈 응답 처리는 자동 테스트로 확인했습니다.

이전 실제 Gemini 연결 검증에서 14회 호출로 나루·솔·미오의 완성된 발언 3개와 사용자 개입을 확인했습니다. 실제 429 응답 이후 대화 재개와 생성기 정리도 확인했습니다. 이전 4초 간격 설정으로 별도 Gemini 웹 대화를 실행해 10개 채팅이 각각 단일 `speech_chunk`로 전달되는 것을 확인했습니다. 해당 채팅은 44~85자이며 표시 간격은 5.48~6.83초였습니다. 브라우저에서도 나루·솔·미오의 완성된 채팅과 정상 연결을 확인했습니다.

앱이 미리 요청을 지연하는 RPM/TPM 설정과 호출 횟수 예산은 기본 0(비활성)입니다. 동시 호출은 최대 4개이고, 실제 429 오류의 재시도 처리는 유지합니다. 결제 등급을 바꾸지 않습니다.

## 알려진 한계

- 공급자의 실제 할당량이나 네트워크 오류로 메시지가 읽기 간격보다 늦어질 수 있습니다.
- 로컬 모델은 외부 할당량이 없지만 GPU·메모리·문맥 길이에 따라 느려질 수 있습니다. 첫 실행에는 모델 로딩 시간이 추가됩니다.
- 완성된 채팅을 즉시 표시하므로 화면에 나온 문장의 일부만 잘라내는 연출은 없습니다. 사용자 개입은 준비 중인 다음 메시지를 취소합니다.
- 모델의 반복, 과장, 사실 오류와 장시간 대화의 자연스러움은 별도 평가가 필요합니다.
- 최근 문맥과 짧은 개인 기억을 사용하므로 오래된 세부 사항이 소실될 수 있습니다.
- 서버 재시작 후 저장 기록 조회는 가능하지만 세션 자동 재개는 일반 실행의 기능에 포함하지 않습니다.
- 무인 서버 운영·로그인·공개 인터넷 서비스용 보안 설계는 범위에 포함하지 않았습니다.
